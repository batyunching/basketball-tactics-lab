# Phase 3：3v3 影片重建

上方選單 **🎥 影片分析**。所有影片與分析結果只存在老師這台電腦的瀏覽器（IndexedDB），偵測在瀏覽器內執行，影片不會上傳；不做人臉辨識。

## 拍攝建議（決定自動追蹤成功率）

- 固定、較高位置的鏡頭（看台、二樓、架高的腳架），能拍到整個半場與底線、罰球線。
- 3v3 半場；兩隊穿**紅色、藍色**背心，背號清楚；裁判、觀眾盡量不入鏡。
- 10～30 秒、光線充足；MP4（H.264）最穩定，也接受 WebM、MOV（500MB 內）。

## 操作流程

| 步驟 | 做什麼 |
| --- | --- |
| 匯入 | 勾選「已取得授權」→ 選擇影片。可隨時刪除（影片、軌跡、分析一起刪除）。 |
| ① 片段 | 選要分析的 10～30 秒（不修改原檔）。 |
| ② 球場校正 | 暫停在清楚的畫面，依序選校正點並點影片上的位置（至少 4 點，建議 6 點以上分散）。綠色線條會疊在影片上，對齊即正確；顯示平均誤差（公尺）。 |
| ③ 自動追蹤 | 選每秒取樣張數（2／5／10），在瀏覽器執行 YOLOX 人物偵測＋多目標追蹤＋背心顏色判斷。第一次會下載約 20MB 模型。可取消。 |
| ④ 身分校正 | 系統**不會**把追蹤編號當背號。按「看」跳到該軌跡畫面，依背號指派給紅1…藍3（可多段指派同一人、標為非球員），勾選「已確認」。 |
| ⑤ 人工關鍵影格 | 在任一時間點建立關鍵影格，拖曳球場上的球員，或選球員後點影片上他的腳底位置（已校正時）。可設定持球者與說明。人工位置優先於自動偵測，兩個關鍵影格之間自動內插（最多 3 秒）。自動追蹤失敗時，只用這一步也能完成重建。 |
| ⑥ 對照回放 | 左影片、右虛擬球場同步；逐格、慢速、過去 2 秒軌跡。橘色虛線圈＋「?」= 不確定，下方列出原因。可「轉成戰術動畫」（到白板編輯、發布成教材）或「匯出軌跡 JSON」。 |

## 不確定標記

| 標記 | 意義 |
| --- | --- |
| 偵測信心低 | 模型不太確定這是人 |
| 重疊 | 與其他球員框重疊，身分可能互換 |
| 落在場外 | 換算後在場外：校正不準或偵測到場邊的人 |
| 隊色不明確 | 背心顏色無法判斷 |
| 以速度推估 | 短暫被擋住，用移動速度推算 |
| 內插補上 | 兩個可信位置之間補上 |

## 輸出欄位（匯出軌跡 JSON）

每個樣本：`timeMs, trackId, playerId, team, jerseyNumber, courtPosition, detectionConfidence, identityConfidence, reviewStatus, positionSource (observed / interpolated / predicted / manual), flags`。

## 技術與測試

- 偵測：YOLOX-Tiny（Apache-2.0，`apps/web/public/models/`），onnxruntime-web（WASM）在瀏覽器執行，只取「person」類別。
- 追蹤：ByteTrack 精簡版（高／低信心兩段配對、等速預測、短暫遺失推估）。
- 校正：正規化 DLT 單應性，腳底點（框底部中央）換算球場公尺座標。
- 測試：
  - 單元測試 24 項：單應性（含 ±3px 點擊雜訊誤差 < 0.3m）、YOLOX 解碼（**真實模型＋真實照片**推論）、追蹤（遮擋、低信心、低影格率）、隊色、軌跡欄位、內插上限、轉戰術、片段規則。
  - E2E：程式產生的透視球場測試影片（`apps/web/e2e/fixtures/make_clip.py`）跑完整流程；瀏覽器內實際執行模型，三個人形全部被追蹤到，隊色判斷正確，指派後與真實路徑平均誤差 < 1 公尺。
  - ⚠ 測試影片是合成的，**不代表真實籃球影片的準確度**。依計畫書第九節，須以校園實拍短片建立人工標註真值後再評估偵測召回率、隊色準確率、ID 切換、定位誤差與教師校正負擔。

## 已知限制

- 背號不做自動辨識（OCR），一律由老師指派。
- 球的位置與球權不自動追蹤，由老師在關鍵影格指定持球者；不會把「靠近籃框」當成得分。
- GitHub Pages 無法開啟多執行緒，偵測速度約每張 0.2～0.5 秒（依電腦而定）；30 秒×5 張／秒約需 1 分鐘。
- 只支援半場（攻上方籃框）；鏡頭移動或變焦的影片，校正會失準。
- 影片只存在一台電腦，未上傳雲端（隱私優先）；換電腦需重新匯入。
