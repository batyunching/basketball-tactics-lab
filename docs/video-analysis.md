# 影片分析：3v3 影片重建與籃球追蹤

上方選單 **🎥 影片分析**。所有影片與分析結果只存在老師這台電腦的瀏覽器（IndexedDB），偵測在瀏覽器內執行，影片不會上傳；不做人臉辨識。

## 拍攝建議（決定自動追蹤成功率）

- 固定、較高位置的鏡頭（看台、二樓、架高的腳架），能拍到整個半場與底線、罰球線。
- 3v3 半場；兩隊穿**紅色、藍色**背心，背號清楚；裁判、觀眾盡量不入鏡。
- 10 秒～3 分鐘（例如從開始進攻到投進一球）、光線充足；MP4（H.264）最穩定，也接受 WebM、MOV（1GB 內）。

## 操作流程

| 步驟 | 做什麼 |
| --- | --- |
| 匯入 | 勾選「已取得授權」→ 選擇影片。可隨時刪除（影片、軌跡、分析一起刪除）。 |
| ① 片段 | 選要分析的 10 秒～3 分鐘（不修改原檔）。超過 1 分鐘會提示分析較久。 |
| ② 球場校正 | 暫停在清楚的畫面，依序選校正點並點影片上的位置（至少 4 點，建議 6 點以上分散）。綠色線條會疊在影片上，對齊即正確；顯示平均誤差（公尺）。下方「籃框位置」：按「標記籃框」後點一下籃框中心（判斷進球用；可調整寬度）。沒標記時，追蹤後系統會估計一個位置（黃色），請確認。 |
| ③ 自動追蹤 | 選每秒取樣張數（2／5／10），在瀏覽器執行 YOLOX 人物偵測＋多目標追蹤＋背心顏色判斷。預設同時**追蹤籃球**：判斷每個時間誰持球、找出每次出手並判斷進球／沒進／無法判定（見下節）。第一次會下載約 20MB 模型。可取消；也可只「重新分析籃球」。 |
| ④ 身分校正 | 系統**不會**把追蹤編號當背號。按「看」跳到該軌跡畫面，依背號指派給紅1…藍3（可多段指派同一人、標為非球員），勾選「已確認」。 |
| ⑤ 人工關鍵影格 | 在任一時間點建立關鍵影格，拖曳球場上的球員，或選球員後點影片上他的腳底位置（已校正時）。可設定持球者與說明。人工位置優先於自動偵測，兩個關鍵影格之間自動內插（最多 3 秒）。自動追蹤失敗時，只用這一步也能完成重建。 |
| ⑥ 對照回放 | 左影片、右虛擬球場同步；逐格、慢速、過去 2 秒軌跡。橘色虛線圈＋「?」= 不確定，下方列出原因。影片上的橘色圈是籃球（實線＝看到、虛線＝推估），尾巴是最近 0.8 秒的路徑，出手後籃框上方顯示「進球！／沒進／無法判定」；虛擬球場的持球者也跟著籃球追蹤。可「轉成戰術動畫」或「匯出軌跡 JSON」。 |
| ⑦ AI 戰術分析 | 按「匯入籃球追蹤結果」，系統偵測的持球與出手會變成**待確認**標記（🤖 系統偵測・信心），老師確認（或改成進／未進）後才用於分析與得分。 |

## 籃球追蹤與進球判斷

1. **找球（每秒 5～10 張）**：先用片段中 25 張畫面取中位數當「背景」，再找與背景不同、**橘色、高飽和、圓形、大小約為身高 1/7** 的色塊；YOLOX 偵測到的 sports ball 也一起使用。
   - 飽和度門檻排除皮膚與木地板；色相範圍排除紅色球衣；背景比對排除橘色禁區、場邊角錐等不會動的東西。
2. **連成軌跡**：把每格的候選連成一條最合理的路徑（最短路徑）。速度超過約 14 m/s 的跳動不允許，零星誤判會被跳過；0.6 秒內被擋住的空檔用內插補上並標「推估」。
3. **持球**：球心在某位球員框的手部範圍（左右放寬 30%、頭以下）且持續約 0.3 秒以上。
4. **出手**：球離開持球者、往上飛、接近籃框。
5. **精細分析**：球接近籃框的時段（前 0.9 秒、後 1.4 秒）改用每秒 30 張重新找球，避免錯過穿過籃框的瞬間。
6. **進球判斷**（需要籃框位置）：

| 判定 | 看得到的證據 |
| --- | --- |
| 進球（信心高） | 球先在籃框上方，再落入籃網區（或接著出現在籃框正下方），沒有往外彈 |
| 進球（信心中） | 球從籃框上方直接出現在籃框正下方，中間被籃網遮住 |
| 沒進 | 碰框後往上彈、在籃框高度往外彈開，或從籃框旁邊落下 |
| 無法判定 | 球在籃框附近幾乎沒被拍到（被籃板、籃網、球員擋住）——**系統不猜**，由老師決定 |

系統判斷的持球與進球都只是「建議」，要在 ⑦ 由老師確認後才算數。

**拍攝建議（籃球）**：鏡頭固定、看得到整個籃框與籃網；不要逆光；球員以外的橘色物品盡量不要移動；30fps 以上。

## 不確定標記

| 標記 | 意義 |
| --- | --- |
| 偵測信心低 | 模型不太確定這是人 |
| 重疊 | 與其他球員框重疊，身分可能互換 |
| 落在場外 | 換算後在場外：校正不準或偵測到場邊的人 |
| 隊色不明確 | 背心顏色無法判斷 |
| 以速度推估 | 短暫被擋住，用移動速度推算 |
| 內插補上 | 兩個可信位置之間補上 |

## 輸出欄位（匯出軌跡 JSON）

每個樣本：`timeMs, trackId, playerId, team, jerseyNumber, courtPosition, detectionConfidence, identityConfidence, reviewStatus, positionSource (observed / interpolated / predicted / manual), flags`。

## 技術與測試

- 偵測：YOLOX-Tiny（Apache-2.0，`apps/web/public/models/`），onnxruntime-web（WASM）在瀏覽器執行，只取「person」類別。
- 追蹤：ByteTrack 精簡版（高／低信心兩段配對、等速預測、短暫遺失推估）。
- 校正：正規化 DLT 單應性，腳底點（框底部中央）換算球場公尺座標。
- 測試：
  - 單元測試 24 項：單應性（含 ±3px 點擊雜訊誤差 < 0.3m）、YOLOX 解碼（**真實模型＋真實照片**推論）、追蹤（遮擋、低信心、低影格率）、隊色、軌跡欄位、內插上限、轉戰術、片段規則。
  - E2E：程式產生的透視球場測試影片（`apps/web/e2e/fixtures/make_clip.py`）跑完整流程；瀏覽器內實際執行模型，三個人形全部被追蹤到，隊色判斷正確，指派後與真實路徑平均誤差 < 1 公尺。
  - 籃球：單元測試 18 項（顏色候選、背景、靜態物、追蹤、持球、出手／進球／無法判定、取樣率差異、籃框估計）＋合成基準（見品質評估文件）；E2E 用程式繪製的 3v3 短片（`make_ball_clip.py`：上籃進球＋三分沒進，含籃網與場邊橘色角錐），在瀏覽器實際執行，2 次出手全部找到且進／沒進判斷正確、出手者正確，匯入 ⑦ 後 AI 分析採用。
  - ⚠ 測試影片是合成的，**不代表真實籃球影片的準確度**。依計畫書第九節，須以校園實拍短片建立人工標註真值後再評估偵測召回率、隊色準確率、ID 切換、定位誤差與教師校正負擔。

## 已知限制

- 背號不做自動辨識（OCR），一律由老師指派。
- 籃球只用顏色、形狀與時間連續性判斷：球被身體完全擋住、球衣或場地是橘色、光線很暗時會找不到或找錯；鏡頭移動會讓籃框位置失準。只判斷畫面上的「深淺」，無法分辨球在籃框前或後，所以「從籃框正下方出現」只給中信心。
- 球在空中時無法換算球場座標（不在地面上），虛擬球場只顯示持球者。
- GitHub Pages 無法開啟多執行緒，偵測速度約每張 0.2～0.5 秒（依電腦而定）。系統依長度建議取樣：30 秒內 5 張／秒、90 秒內 3 張／秒、3 分鐘 2 張／秒（約 360 張，約 2～3 分鐘）。分析期間請保持分頁開著。
- 只支援半場（攻上方籃框）；鏡頭移動或變焦的影片，校正會失準。
- 影片只存在一台電腦，未上傳雲端（隱私優先）；換電腦需重新匯入。
