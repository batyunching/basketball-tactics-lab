# 需求與完成狀態（Phase 1＋2）

| ID | 模組 | Phase 1 狀態 |
| --- | --- | --- |
| M01 | 球場引擎 | ✅ 半場（直向、籃框在上）／全場（橫向）、1v1～5v5、換邊進攻（整份戰術鏡射）、FIBA 28×15m 參數化標線、縮放（按鈕／滾輪／雙指）與平移、全螢幕、專注模式 |
| M02 | 球員互動 | ✅ 紅藍圓形編號、滑鼠＋觸控拖曳（Pointer Events）、選取、鎖定、座標約束（含界外 1m）、背號編輯（同隊唯一）、數值座標輸入、方向鍵微調、復原重做（拖曳合併為一筆） |
| M03 | 籃球與球權 | ✅ 指定持球者、球隨持球人移動、拖球交球／傳球、傳球／運球／投籃事件、攻守轉換、動畫中球的飛行（拋物線放大） |
| M04 | 教學畫筆 | ✅ 跑動實線、傳球虛線（終點吸附接球者）、運球波浪、掩護 T 字、標註圈、防守色塊、5 色、橡皮擦、清除本步 |
| M05 | 預設隊形 | ✅ 內建五組；保存雙方位置、球權、方向、人數、場地；新增／覆寫／改名／複製／刪除／還原內建，不限五組 |
| M06 | 動畫編輯器 | ✅ 多步驟、easeInOut 平滑插值、上／下一步、播放／暫停、時間軸拖曳、0.25～2 倍速、循環、步驟排序、移動時間、教師註解 |
| 儲存 | IndexedDB | ✅ 0.5 秒自動儲存、重新整理恢復、多份戰術檔、revision 遞增、離線快取（service worker） |
| 交換 | JSON | ✅ 匯出（戰術＋隊形）、匯入（zod 驗證、版本檢查、匯入為新專案）、PNG 匯出 |
| M07 | 教材庫 | ✅ 六套：傳切、擋拆、無球掩護、快攻三打二、人盯人與協防、2-3 區域輪轉；每套 5～7 步動畫、學習目標、動作要點；可複製到白板修改 |
| M08 | 學生挑戰 | ✅ 站位挑戰、跑位預測、戰術選擇；多個合理解（多判定區、多正確選項、部分分）；提示、重試、解說；教師回饋 |
| 權限 | 教師／學生 | ✅ 學生端唯讀；任務以代碼讀取教材快照；RLS 17 項測試 |
| 雲端 | Supabase | ✅ Email 教師登入、學生匿名登入、戰術同步、任務、作答、回饋；未設定時完整的本機模式 |
| 同步 | 離線與衝突 | ✅ 離線佇列、operationId 冪等重送、修訂版 compare-and-swap、衝突三種處理、不靜默覆寫 |

## 尚未完成（依計畫屬後續階段，或本階段刻意不做）

- 教師自行出題（題目編輯器）：目前題目來自六套內建教材；教師自己的戰術可發布為「觀看」用途需後續加入。
- 隊形（formations）尚未雲端同步，只存本機。
- 分數由學生端計算後上傳（教師可看作答明細核對），尚未在伺服器端重新評分。
- 雲端流程（登入、發布、繳交、回饋）的自動化測試以 RLS 測試＋同步引擎模擬測試涵蓋；真實 Supabase 的端對端測試需在設定完成後手動驗收。
- 步驟之間「事件時間點」目前固定在段落中段出手，尚不能逐事件調整時間。
- 戰術線不會隨球員移動而自動跟著走（線是畫在該步驟的固定位置）。
- 無「多選一起拖曳」與框選。
- 尚未做 PWA 安裝圖示的多尺寸 PNG（目前只有 SVG 圖示）。
- 未在實體觸控大屏幕／iPad 實機驗證，只用 Playwright 模擬觸控測試；建議上課前實機試一次。

## Phase 3 完成狀態（3v3 影片重建）

| 計畫書要求 | 狀態 |
| --- | --- |
| 可上傳／裁切／刪除 3v3 半場短片 | ✅ 匯入（格式、大小驗證、授權確認）、10 秒～3 分鐘片段選擇、刪除（影片＋軌跡＋分析） |
| 能手動校正球場、隊別及背號 | ✅ 12 個校正點、單應性與誤差顯示、影片疊線；隊色自動判斷＋老師指派背號 |
| 能產生含不確定標記之球員軌跡 | ✅ 偵測、追蹤、球場座標、7 種不確定原因、計畫書欄位輸出 |
| 原影片與虛擬球場同步回放 | ✅ 共用時間軸、逐格、慢速、軌跡尾巴、不確定標示 |
| 校正資料可保存，失敗時可人工建立關鍵影格 | ✅ 自動儲存；人工關鍵影格＋內插，可完全不靠自動追蹤 |
| 以真實測試影片驗證 | ⏳ 等待校園實拍短片（目前以真實模型＋真實照片、合成透視影片測試流程） |

## Phase 4 完成狀態（AI 戰術分析）

| 計畫書要求 | 狀態 |
| --- | --- |
| 偵測傳球、空切、掩護、突破、協防等事件 | ✅ 規則式引擎（另含失誤、得分、得分關鍵鏈）；子類型：傳切、擋拆、無球掩護、協防分球 |
| 教師確認得分與球權 | ✅ 在影片時間點標記持球者／出手與進球，逐筆勾選確認；可從關鍵影格匯入 |
| 繁中輸出時間點、相關球員、可見證據、戰術推論、教學建議、信心 | ✅ 每個事件四段文字＋四級信心（高／中／低／證據不足） |
| 證據不足時明確說無法確認 | ✅ 未確認標記、位置缺漏、資料品質過低 → 「證據不足」並寫出原因；沒有球權標記時不推論傳球與得分 |
| 教師可編輯結果 | ✅ 確認、否決、修改證據／推論／建議、新增漏掉的事件；重跑分析保留已審核結果 |
| 確認後轉為學生互動教材 | ✅ 只用確認事件 → 動畫步驟＋自動出題（跑位預測、站位、傳球、協防、得分關鍵）；可本機連結（教材壓縮在連結內、竄改會被拒絕）或雲端任務發布 |
| 端到端測試 | ✅ `e2e/phase4-ai.spec.ts`（桌機＋觸控平板） |
| 權限與刪除測試 | ✅ RLS 補 4 項刪除測試；e2e 驗證刪除影片連帶清除 AI 分析、刪除自訂教材 |
| 品質評估 | ✅ 合成基準＋教師審核即時評估，見 [quality-evaluation.md](quality-evaluation.md) |
| 5v5 擴充規劃 | ✅ 見 [5v5-plan.md](5v5-plan.md) |
| 以真實比賽影片驗證準確度 | ⏳ 等待校園實拍短片（驗證計畫已寫在品質評估文件第 6 節） |

尚未完成／刻意不做：
- 不使用雲端大型語言模型（依教師選擇「規則式分析」）；文字由規則模板產生，教師可修改。
- 籃球追蹤與進球判斷只作為建議，須由教師確認後才用於分析與得分（見下方「籃球追蹤」）。
- 只支援半場、進攻方向朝右；全場見 5v5 規劃 5B。

## 籃球追蹤（影片分析加強）

| 需求 | 狀態 |
| --- | --- |
| 判別籃球 | ✅ 背景＋橘色圓形色塊＋YOLOX sports ball；排除皮膚、木地板、紅色球衣、靜止的橘色物品 |
| 籃球移動 | ✅ 時序最短路徑追蹤、短暫遮擋內插；影片疊圖顯示球與 0.8 秒軌跡；判斷每個時間的持球者，虛擬球場同步 |

| 與 AI 戰術分析整合 | ✅ 一鍵匯入成待確認的球權與出手標記，老師確認後才採用 |

| 以真實比賽影片驗證 | ⏳ 等待校園實拍 |
